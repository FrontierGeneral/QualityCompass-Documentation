# Quality Compass — Privacy Policy

**Effective Date:** March 7, 2026
**Last Updated:** March 7, 2026
**Version:** 1.0

---

## 1. Introduction

This Privacy Policy describes how Nexus Frontier ("we," "us," or "our") collects, uses, stores, and protects information through the Quality Compass application ("the App"), a Jira Cloud app available on the Atlassian Marketplace.

Quality Compass is a quality assurance and ticket evaluation management tool that operates entirely within the Atlassian Forge platform. We are committed to protecting the privacy of our users and complying with applicable data protection laws, including the General Data Protection Regulation (GDPR) and the California Consumer Privacy Act (CCPA).

By installing or using Quality Compass, you acknowledge that you have read and understood this Privacy Policy.

---

## 2. Data Controller and Data Processor

- **Data Controller:** The organization ("Customer") that installs and administers Quality Compass on their Atlassian Jira Cloud instance is the Data Controller for End-User Data processed through the App.
- **Data Processor:** Nexus Frontier acts as a Data Processor, processing End-User Data on behalf of the Customer in accordance with this Privacy Policy and our [Data Processing Agreement (DPA)](./dpa).
- **Sub-processor:** Atlassian Pty Ltd is a sub-processor, as all App data is stored within Atlassian's Forge infrastructure.

---

## 3. Data We Collect

### 3.1 Data Collected from Jira

| Data Type | Fields | Purpose |
|-----------|--------|---------|
| **User Identity** | Account ID, Display Name | Identify evaluators, assignees, and administrators |
| **User Email** | Email Address | Fallback display name resolution (not stored persistently) |
| **User Avatar** | Avatar URL | Display user profile images in the App UI |
| **User Groups** | Group Memberships | Determine administrator privileges |
| **Issue Data** | Issue Key, Summary, Status, Priority, Type, Assignee, Reporter, Project, Created Date, Resolution Date | Display ticket context for evaluations and analytics |
| **Project Data** | Project Key, Name, Avatar URL | Configure allowed projects for evaluation |

### 3.2 Data Generated by the App

| Data Type | Description | Contains Personal Data |
|-----------|-------------|----------------------|
| **Ticket Evaluations** | Quality scores, feedback text, evaluator identity, timestamps | Yes |
| **Evaluator Name Mapping** | Cache linking Account IDs to Display Names | Yes |
| **Role Assignments** | User-to-role mappings per project (RBAC) | Yes |
| **Audit Logs** | Records of administrative actions and data changes | Yes |
| **Project Access Configuration** | List of projects enabled for evaluation | Yes |
| **Coverage Targets** | Quality coverage target percentages | No |
| **Evaluation Criteria** | Scoring criteria definitions | No |
| **User Preferences** | Theme selection, selected project | No |
| **GDPR Consent Records** | User consent timestamps and versions | Yes |

### 3.3 Client-Side Data

The App temporarily caches data in the user's browser (IndexedDB and in-memory) to improve performance. Client-side caches are stored only in the individual user's browser, expire automatically, and are not transmitted to any external service.

## 4. How We Use Data

We use the collected data solely to provide and operate Quality Compass functionality:

| Purpose | Legal Basis (GDPR) |
|---------|-------------------|
| Displaying ticket evaluation forms and scores | Performance of contract (Art. 6(1)(b)) |
| Generating analytics dashboards and reports | Performance of contract (Art. 6(1)(b)) |
| Identifying evaluators and agents in reports | Legitimate interest (Art. 6(1)(f)) |
| Enforcing role-based access control (RBAC) | Legitimate interest (Art. 6(1)(f)) |
| Maintaining audit trails of administrative actions | Legal obligation / Legitimate interest |
| Caching user names for display performance | Legitimate interest (Art. 6(1)(f)) |

We do **not** use data for advertising, profiling, selling to third parties, or training machine learning models.

---

## 5. Where Data Is Stored

All server-side data is stored in **Atlassian Forge Key-Value Storage** — hosted and managed entirely by Atlassian, encrypted at rest (AES-256) and in transit (TLS 1.2+), subject to Atlassian's compliance certifications (SOC 2, ISO 27001, ISO 27018).

Quality Compass does **not** store any data on servers owned or operated by Nexus Frontier.

Data residency is governed by [Atlassian's Data Residency policies](https://support.atlassian.com/security-and-access-policies/docs/understand-data-residency/).

---

## 6. Data Sharing and Third Parties

Quality Compass does **not** send data to any external servers, use third-party analytics or tracking, share data with sub-processors beyond Atlassian, or make outbound network requests outside Atlassian's infrastructure.

| Sub-processor | Purpose | Location |
|---------------|---------|----------|
| Atlassian Pty Ltd | Cloud infrastructure (Forge platform) and Jira Cloud APIs | Per Atlassian's data residency settings |

## 8. Data Subject Rights (GDPR)

Quality Compass includes built-in GDPR compliance features:

- **Right of Access (Art. 15):** Data export function for all personal data per user
- **Right to Erasure (Art. 17):** Data deletion across evaluations, logs, preferences, and roles
- **Right to Rectification (Art. 16):** Update display names via Jira profile
- **Right to Data Portability (Art. 20):** Structured, machine-readable export
- **Right to Object (Art. 21):** Contact your Jira administrator to modify access
- **Right to Restriction (Art. 18):** Administrators can restrict access via RBAC

Data subject requests should be directed to your organization's Jira administrator. For requests that cannot be fulfilled through the App, contact **[support@nexusfrontier.net](mailto:support@nexusfrontier.net)**.

We do **not** sell personal information. California residents may request disclosure or deletion of personal information by contacting their Jira administrator or emailing us.
