## 1. Introduction

This Privacy Policy describes how Nexus Frontier ("we," "us," or "our") collects, uses, stores, and protects information through the Quality Compass application ("the App"), a Jira Cloud app available on the Atlassian Marketplace.

Quality Compass is a quality assurance and ticket evaluation management tool that operates entirely within the Atlassian Forge platform. We are committed to protecting the privacy of our users and complying with applicable data protection laws, including the General Data Protection Regulation (GDPR) and the California Consumer Privacy Act (CCPA).

By installing or using Quality Compass, you acknowledge that you have read and understood this Privacy Policy.

---

## 2. Data Controller and Data Processor

- **Data Controller:** The organization ("Customer") that installs and administers Quality Compass on their Atlassian Jira Cloud instance is the Data Controller for End-User Data processed through the App.
- **Data Processor:** Nexus Frontier acts as a Data Processor, processing End-User Data on behalf of the Customer in accordance with this Privacy Policy and our Data Processing Agreement (DPA).
- **Sub-processor:** Atlassian Pty Ltd is a sub-processor, as all App data is stored within Atlassian's Forge infrastructure.

## 3. Data We Collect

### 3.1 Data Collected from Jira

The App accesses the following data from the Customer's Jira Cloud instance through Atlassian-provided APIs:

| Data Type | Fields | Purpose |
|-----------|--------|---------|
| **User Identity** | Account ID, Display Name | Identify evaluators, assignees, and administrators |
| **User Email** | Email Address | Fallback display name resolution (not stored persistently) |
| **User Avatar** | Avatar URL | Display user profile images in the App UI |
| **User Groups** | Group Memberships | Determine administrator privileges |
| **Issue Data** | Issue Key, Summary, Status, Priority, Type, Assignee, Reporter, Project, Created Date, Resolution Date | Display ticket context for evaluations and analytics |
| **Project Data** | Project Key, Name, Avatar URL | Configure allowed projects for evaluation |

### 3.2 Data Generated by the App

The App creates and stores the following data through user interactions:

| Data Type | Description | Contains Personal Data |
|-----------|-------------|----------------------|
| **Ticket Evaluations** | Quality scores, feedback text, evaluator identity, timestamps | Yes (evaluator Account ID, Display Name) |
| **Evaluator Name Mapping** | Cache linking Account IDs to Display Names | Yes |
| **Role Assignments** | User-to-role mappings per project (RBAC) | Yes (Account IDs) |
| **Audit Logs** | Records of administrative actions and data changes | Yes (Account IDs) |
| **Project Access Configuration** | List of projects enabled for evaluation, including who added them | Yes (Account IDs) |
| **Coverage Targets** | Quality coverage target percentages | No |
| **Evaluation Criteria** | Scoring criteria definitions | No |
| **User Preferences** | Theme selection (light/dark), selected project | No |
| **GDPR Consent Records** | User consent timestamps and versions | Yes (Account IDs) |
| **Rate Limit Data** | Request counts per user per endpoint | Yes (Account IDs) |

### 3.3 Client-Side Data

The App temporarily caches data in the user's browser to improve performance:

| Storage Type | Data | Retention |
|--------------|------|-----------|
| **IndexedDB** (`qc-persisted-cache`) | Analytics summaries, ticket metadata, evaluator analytics | 5 minutes to 2 hours (varies by data type) |
| **In-Memory Cache** | Evaluations, analytics, user data, criteria | 1 minute to 2 hours (varies by data type) |

Client-side caches are stored only in the individual user's browser and are not transmitted to any external service.

## 5. Where Data Is Stored

### 5.1 Server-Side Storage

All server-side data is stored in **Atlassian Forge Key-Value Storage**, which is:

- Hosted and managed entirely by Atlassian within their cloud infrastructure
- Encrypted at rest using AES-256 encryption
- Encrypted in transit using TLS 1.2 or higher
- Subject to Atlassian's own security and compliance certifications (SOC 2, ISO 27001, ISO 27018)
- Isolated per app and per Jira site (multi-tenant isolation)

Quality Compass does **not** store any data on servers owned or operated by Nexus Frontier.

### 5.2 Client-Side Storage

Temporary caches are stored in the user's browser (IndexedDB and in-memory) and remain on the user's device. These caches expire automatically and can be cleared by the user at any time through standard browser controls.

### 5.3 Data Residency

Because all data is stored within Atlassian Forge infrastructure, data residency is governed by Atlassian's own data residency policies. Quality Compass does not independently control or offer data residency selection. Please refer to [Atlassian's Data Residency documentation](https://support.atlassian.com/security-and-access-policies/docs/understand-data-residency/) for details on where your data is stored.

## 7. Data Retention

### 7.1 Retention Periods

| Data Category | Retention Period | Justification |
|---------------|-----------------|---------------|
| Ticket Evaluations | 365 days | Operational need for quality trend analysis |
| Audit Logs | 90 days | Compliance and security monitoring |
| User Preferences | 730 days | User convenience across sessions |
| Analytics / Derived Data | 180 days | Reporting and trend analysis |
| Temporary / Cache Data | 7 days (server) / auto-expiring (client) | Performance optimization |

### 7.2 Data After Uninstallation

When Quality Compass is uninstalled from a Jira Cloud site, all data stored in Forge Key-Value Storage for that installation is handled according to Atlassian's standard Forge data lifecycle. Atlassian's platform retains uninstalled app data for up to **28 days** as a soft-delete grace period — during which the data is inaccessible to the app but recoverable if the customer reinstalls the app within 21 days. After 28 days, all data is permanently deleted by the Atlassian platform.

Quality Compass does not independently retain or extend this retention period. We do not maintain any data store outside of Atlassian Forge.

Client-side caches (IndexedDB) will persist in individual browsers until manually cleared or until the cached entries expire.

Reference: [Atlassian Forge Data lifecycle for hosted storage](https://developer.atlassian.com/platform/forge/storage-reference/hosted-storage-data-lifecycle/).

### 7.3 Personal Data Reporting to Atlassian

In addition to the in-app data subject rights described in Section 8, Quality Compass implements Atlassian's **Personal Data Reporting API** as required for Marketplace cloud apps that store user personal data. On a weekly cadence, the App reports to Atlassian the list of Atlassian Account IDs for which it currently stores personal data, along with the timestamp at which each user's data was last refreshed.

When Atlassian indicates that an account has been **closed**, the App automatically erases that user's personal data from Forge Storage (evaluations, name cache entries, preferences, consent records, and the personal-data index entry). When Atlassian indicates that an account's data has been **updated**, the App refreshes its cached copy from the Atlassian user APIs.

This mechanism complements — and does not replace — the user-initiated data subject rights below. Reference: [Atlassian user privacy guide for app developers](https://developer.atlassian.com/platform/forge/user-privacy-guidelines/).

## 8. Data Subject Rights (GDPR)

Quality Compass includes built-in GDPR compliance features. Users and administrators can exercise the following rights:

### 8.1 Right of Access (Article 15)

Users can request an export of all personal data associated with their Account ID. The App provides a data export function that compiles:
- All evaluations created by the user
- Audit log entries associated with the user
- User preferences and consent records
- Role assignments

### 8.2 Right to Erasure (Article 17)

Users can request deletion of their personal data. The App provides a data deletion function that removes:
- All evaluations created by the user
- Audit log entries associated with the user
- User preferences and consent records
- Name cache entries
- Role assignments

### 8.3 Right to Rectification (Article 16)

Display names are sourced from Jira user profiles. To correct a display name, users should update their Jira profile directly. The App will reflect changes upon next data refresh.

### 8.4 Right to Data Portability (Article 20)

The data export function provides personal data in a structured, machine-readable format.

### 8.5 Right to Object (Article 21)

Users may object to processing of their personal data by contacting their organization's Jira administrator, who can modify the user's role assignments or remove their data.

### 8.6 Right to Restriction of Processing (Article 18)

Administrators can restrict a user's access through the RBAC system by removing role assignments or adjusting permissions.

### 8.7 How to Exercise Your Rights

Data subject requests should be directed to your organization's Jira administrator in the first instance. For requests that cannot be fulfilled through the App's built-in features, contact us at **support@nexusfrontier.net**.

## 16. Jira API Scope Justification

Quality Compass requests the following Atlassian API scopes, each with a specific, limited purpose:

| Scope | Purpose |
|-------|---------|
| `read:jira-work` | Read issue data (key, summary, status, priority, assignee, reporter) for evaluation context and analytics |
| `write:jira-work` | No direct writes to Jira issues — scope retained for future feature compatibility |
| `storage:app` | Store and retrieve evaluation data, criteria, roles, audit logs, and user preferences in Forge Key-Value Storage |
| `read:jira-user` | Read user Account IDs, Display Names, and Group Memberships for user identification and administrator verification |
| `report:personal-data` | Required by Atlassian's Personal Data Reporting API. Allows the App to report to Atlassian, on a weekly schedule, the list of Account IDs for which it stores personal data so Atlassian can notify the App when accounts are closed or updated. See Section 7.3. |
